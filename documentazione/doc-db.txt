// TABELLA QUOTES (PREVENTIVI)

id -> uuid 
company_id -> foreign_key che collega a tenant 
client_id -> foreign_key che collega al cliente 
created_by -> foreign_key che lo collega a user (chi ha creato questo preventivo)
number -> numero commerciale preventivo preventivo (es. PREV-2026-001) 
version -> versione preventivo -> (es. invio preventivo versione 1, se dopo aggiungo modifiche passa a version 2)
status -> stato preventivo ('inviato','accettato','rifiutato',ecc)
title -> titolo preventivo (es. Sostituzione caldaia)
description -> descrizione più dettagliata del lavoro (es. Fornitura e installazione di una nuova caldaia a condensazione, compreso adeguamento dei collegamenti idraulici e collaudo finale.) 
subtotal -> totale del prezzo dei prodotti senza scontistica (es. caldaia 1000 + manodopera 500 = subtotal 1500)
discount_total -> prezzo finale con sconto -> (es. caldaia 1000 + mano d'opera 5000 = subtotal 1500 + sconto 50% = discount_total 750)
taxable_amount -> importo in cui viene calcolata l'iva (es. caldaia 1500 + manodopera 500 + no sconti = 1500 di prezzo da tassare)
tax_total -> totale iva (quanto si è pagato di iva per quel preventivo es. preventivo viene 1500 euro e di tax_total sarà il 22%(esempio) di 1500)
total -> prezzo finale del preventivo (compreso di tutto anche di iva)
currency -> valuta (es. EUR,USD)
valida_until -> preventivo valido fino a 
sent_at -> quando è stato inviato il preventivo 
viewed_at -> quando il cliente ha visualizzato preventivo 
accepted_at -> quando il preventivo è stato accettato 
rejected_at -> quando il preventivo è stato rifiutato 
timestamps -> created_at e updated_at 
deleted_at -> softDelete

//TABELLA QUOTES ITEM
// tabella per ogni item (voce) del preventivo

id -> uuid 
quote_id -> collegamento al quote (preventivo) -> foreignKey con quote relazione N->1 (una quote ha tanti item)
product_id -> collegamento al product -> foreignkey con products -> nullable poichè in un preventivo può non esserci qualcosa (es. consulenza) 
description -> descrizione item (es. inserimento del nome del prodotto es. Caldaia Vailant 24kw, se domani cambiamo product qui non cambia) (è come uno storico degli item)
unit -> unità di misura dell'item (es. metri:m,pezzi:pz,ore:h)
quantity -> quanti pezzi stai vendendo (es. caldaia 2 quantity)
unit_price -> prezzo per ogni singola unità (es. tubo 15$ al m)
discount_type -> indica come viene applicato lo sconto (es. percentuale o sconto fisso) -> nullable
discount_values -> valore dello sconto (es. se type è percentiual e value è 10 allora si applicherà sconto del 10% se fixed allora sconto di 10 $)
vat_race -> iva applicata al singolo pezzo (item)
tax_amount -> importo iva da pagare per ogni singolo pezzo 
total -> prezzo finale compreso di scontistica e iva 
sort_order -> ordine dell'item su preventivo (es. caldaia sort_order 1, tubo sort_order 2,ecc)
timestamps() -> created_at e updated_at

//---------->NOTE
Potrebbe sembrare ridondante avere:

products.name
products.sale_price

e contemporaneamente:

quote_items.description
quote_items.unit_price

Ma è necessario per lo snapshot storico.

Il prodotto può cambiare.

Il preventivo no.

Esempio:

PRODUCT
sale_price = 1500

Al momento della creazione:

QUOTE_ITEM
unit_price = 1350
description = "Caldaia a condensazione..."

Il valore del preventivo rimane quindi indipendente dal catalogo corrente.
